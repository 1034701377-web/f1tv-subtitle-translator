# 开发与维护

普通 Windows 用户使用便携包，见 [Windows 使用说明](Windows使用说明.md)。本页说明源码开发和发布，不要求用户安装开发环境。

## 从源码运行

需要 Node.js 22 或更新版本。在项目根目录执行：

```text
npm ci
npm run build
npm start
```

打开 http://127.0.0.1:3847/ 配置服务。`start-service.cmd` 优先使用便携包内置运行时；源码开发仍可使用系统 Node.js。只有一份服务可以占用默认端口。

## 代码职责

| 位置 | 用途 |
| --- | --- |
| `app/` | 本机配置、组件安装和配对首页 |
| `src/userscript-entry.js`、`src/floating-controls.js`、`src/overlay.js` | 网页控制台、拖动收起和字幕显示 |
| `extension/` | Chrome 标签页音频采集及弹窗 |
| `lib/`、`server.mjs` | 本机配置、翻译和语音识别接口 |
| `scripts/`、`tests/` | 构建、检查及自动测试 |
| `dist/` | 构建生成的脚本与扩展，安装用，不直接编辑 |
| `demo/`、`experiments/` | 开发演示与未接入正式构建的实验 |

版本以 `package.json` 为准；更新源码后运行构建，保持脚本与扩展版本一致。当前发布版本为 0.9.2。仓库保留 `dist/f1tv-zh.user.js` 作为原有脚本安装地址；扩展构建文件随 Windows 便携包分发。

## 必须保持的行为

- 官方解说：官方定时字幕 → 翻译 → 页面缓存 → 按节目时间显示。
- TR：独立 Track FX 页 → 标签页音频 → Qwen ASR → 翻译 → 跨页传送 → 按节目时间显示。
- 采集与显示独立。关闭字幕不停止采集，API 返回时间不能代替节目时间；50 秒只是观看预留量。
- 不随界面或目录整理更换默认模型。ASR 原文保留，术语纠错只影响译文。
- 保留音频时钟跳变重置、官方时钟校准、窗口去重、句子显示冻结、旧请求失效、来源检查及大小限制等保护。

API 密钥仅写入本机 `.env`，配置接口不读回密钥；留空保留原值。保存设置须保留其他参数，避免覆盖语音识别配置。新的配置用于后续请求；修改识别配置前先停止采集。

## 验证与更新

按修改范围运行最低充分检查：

```text
npm run build
npm run check
npm test
```

纯文档修改确认内容和链接即可；局部代码先跑对应测试。模型 API 对比和真实 F1 TV 采集另行明确安排，不能混入默认测试或把模拟通过说成直播通过。

`app/` 更新后刷新本机首页；服务代码更新后重启服务。`src/`、`extension/` 更新后重新构建、安装脚本或重新加载扩展，再刷新官网页。安排在观看结束后进行。

## Windows 便携包与 GitHub 发布

源码和完整系统在同一个仓库维护，Windows 安装包通过 Releases 分发。GitHub 自动生成的源码压缩包不包含便携运行时；需要附加单独的 Windows 资产。[GitHub Releases 说明](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)

准备的本地资产路径为 `release/F1TV-ZH-Windows-x64-v0.9.2.zip`，包含 Node.js、`ws`、启动入口和已构建组件。保留项目 MIT 许可证，以及随包运行时、依赖的各自许可证。

在 Windows x64 开发环境中，完成构建后执行：

```text
npm run package:windows
npm run verify:release
```

打包阶段从 Node.js 官网下载固定版本并校验 SHA256，按锁文件安装生产依赖；用户收到的便携包不需要再安装运行时或依赖。验证会在独立端口、干净配置和没有系统 Node/npm 的 PATH 下运行，不访问真实模型 API。已有同名发布包不会被覆盖。

GitHub 的普通源码检查只运行构建、测试和语法检查；手动触发或版本 tag 才额外验证便携包，不自动发布。此目录中的 `release/` 与 `local/` 都不会进入源码提交。

发布前仅做必要确认：

1. 从干净目录安装便携包，确认没有系统 Node.js 时也能启动；按 Windows 说明完成安装与配对。
2. 确认构建、检查及测试结果，说明真实验证过的场景及尚未验证的部分。
3. 用白名单打包，排除 `.env`、本机记录、日志、临时文件及开发依赖。源码仓库也不提交这些个人文件。
4. 创建版本对应的 Release，上传 Windows ZIP 和校验值，再确认 README 的下载链接可用。源码使用 GitHub 自动提供的 Source code 下载，不把便携包、密钥或本机记录提交进仓库。

README 保持面向用户的安装入口，较长的维护内容放在本页；仓库内部文档使用相对链接，方便源码和离线包阅读。[GitHub README 说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)
